Role-Based Tab Visibility & Portal Isolation

Technical assessment of navigation scoping, demo mode segregation, and strict role portal confinement for Tourists, Hotel Managers, Community, and Authority users.
Target Platform Swat Tourism Platform (Prod)
Document Status Analysis Report
Target Roles 5 System Personas
Date October 9, 2026

1. Executive Summary

This report analyzes how portal tabs and navigation suites are delivered to different user categories:

  • Demo User / Evaluator: Full system access with the top role switcher bar enabled, permitting instant switching between all 5 roles for demonstrations.
  • Tourist Account: Strict access restricted exclusively to Tourist tabs (Home, Explore, Trips, Safety, Profile). Zero exposure to business or authority interfaces.
  • Hotel Manager / Business: Strict access restricted exclusively to Business portal tabs (Today, Listings, Availability, Reviews, Profile).
  • Community Member: Strict access restricted to Community tabs (Stories, Crafts, Report, Hosts, Profile).
  • Authority / Admin: Strict access restricted to Governance tabs (Overview, Directory, Advisories, Approvals, Cases).

3. Gap Analysis: Why Cross-Role Tabs Appear

Root Causes in Existing Codebase

1. Global Demo Bar Always Mounted: In frontend/src/App.tsx, isDemoMode defaults to true. The black top header bar with DEMO LOGINS: Tourist | Business | Community | Authority | Admin is rendered globally across all screens.

2. Automatic Demo Tourist Token: In frontend/src/context/AuthContext.tsx, guests visiting the root URL automatically acquire a demo token (Sara Ahmed) to enable immediate exploration.

3. Permissive Access Matrix: The helper function canAccessRole() currently allows cross-role viewing for testing flexibility.
